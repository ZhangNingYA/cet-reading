# 项目目标

## 一句话目标

让用户在阅读 CET4/CET6/考研英语内容时，在做题和精读之间切换，并按需获取可靠、可复用、可点击的逐句精读结果。

## 用户流程

1. 用户从考试分类进入试卷列表，选择精读或做题模式；当前提供用户上传的 2025 年 6 月四级第 1 套、2026 年 6 月四级第 1、2 套试卷的非听力部分，以原 PDF 的原文和题目为准。
2. 做题模式创建一次答题记录，按章节切换并保留已填写的答案，提交时统一保存所有章节的作答；题目快照和答案保存到 PostgreSQL，API 判客观题分数，主观题保留人工核对状态。
3. 精读模式保留原文段落，通过章节导航切换内容；直接点击原文中的单词或句子，再按句请求 API。API 优先读取缓存，缓存不存在时创建生成任务。
4. Worker 按句子调用 AI，校验结构化结果并保存数据库。
5. 当前句子在原文中高亮，电脑端侧栏、手机端底部面板显示词义及翻译、结构、句型、词汇四个标签。词汇包括值得学习的重点单词、熟词生义和固定搭配；点击词汇或结构可以高亮原文对应位置，同一句话内切换单词复用结果。
6. 用户可重新生成当前句子的全部精读。生成时保留旧结果，新结果通过校验后更新缓存；失败后可重试。切换章节或模式时，已发起的重新生成继续完成并更新对应句子的缓存。

## 必须满足的质量要求

- 原文和精读结果通过 `source_hash` 对齐。
- 翻译、结构、tokens 必须通过 JSON Schema 校验。
- API 错误、模型错误和空结果不能被标记为成功缓存。
- 提示词和模型版本必须进入缓存键。
- 文章级任务允许部分句子完成，并能从失败处继续。
- 单词高亮使用 token index 或字符范围，不依赖页面重新搜索字符串。
- 试卷内容以用户提供的文件为准，参考答案和 AI 精读分别标明来源。

## 暂不做的事情

- 不把 Astro 改成 SSR。
- 不让浏览器直接调用 AI API。
- 不为 CET4 和 CET6 维护两套后端逻辑。
- 不把 AI 生成的 HTML 直接存入数据库。
