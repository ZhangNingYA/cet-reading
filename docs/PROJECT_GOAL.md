# 项目目标

## 一句话目标

让用户在阅读 CET4/CET6 原文时，按需获取可靠、可复用、可点击的逐句精读结果。

## 用户流程

1. 用户打开一张试卷，只看到原文和文章结构。
2. 用户点击某句话或整篇文章的“开始精读”。
3. 前端向 API 请求精读结果。
4. API 优先读取缓存；缓存不存在时创建生成任务。
5. Worker 按句子调用 AI，校验结构化结果并保存数据库。
6. 前端显示翻译、句型、语法结构和可点击单词。
7. 同一句话再次访问时直接返回已缓存结果。

## 必须满足的质量要求

- 原文和精读结果通过 `source_hash` 对齐。
- 翻译、结构、tokens 必须通过 JSON Schema 校验。
- API 错误、模型错误和空结果不能被标记为成功缓存。
- 提示词和模型版本必须进入缓存键。
- 文章级任务允许部分句子完成，并能从失败处继续。
- 单词高亮使用 token index 或字符范围，不依赖页面重新搜索字符串。

## 暂不做的事情

- 不把 Astro 改成 SSR。
- 不让浏览器直接调用 AI API。
- 不为 CET4 和 CET6 维护两套后端逻辑。
- 不把 AI 生成的 HTML 直接存入数据库。
