# 手动下载试卷后的导入流程

这份文档供 Codex 和项目维护者执行。用户只需下载 PDF 并放入项目，后续分类、整理、导入和上线由执行者完成。

## 用户如何使用

1. 把下载的试卷放到 `data/inbox/`，可以一次放多张，保留下载时的文件名即可。
2. 告诉 Codex：“处理新增试卷”。如文件放在其他位置，提供路径即可。
3. 处理完成后，查看新增试卷和线上验证结果；有确实无法确认的内容时，执行者说明具体缺项。

按用户指定的节奏处理。用户要求“一张一张增加，检查后再继续”时，每轮只完成一张试卷的导入、检查和上线，介绍这一张并提供在线入口，然后等待继续指令；其余 PDF 留在待处理目录。

用户要求“每次选三套，检查合格后自动继续”时，按考试时间和套次分批处理全部当前待导入文件，每批最多三套，末批处理剩余数量。只有当前批次通过内容核对、项目检查、部署及公开站点验证，才进入下一批；不要让用户重复发送“继续”。重复下载不计入新增套数，缺题或来源不完整的文件保留并说明原因，不伪造缺失内容。处理状态记录在 [导入进度](PAPER_IMPORT_PROGRESS.md)。此授权针对当前导入任务，不表示已经安装后台目录监控服务。

Windows 下的默认目录：

```text
\\wsl.localhost\Ubuntu-22.04\home\cyan\projects\cet-reading\data\inbox
```

目前没有监控目录并自动解析 PDF 的后台服务；上述请求会启动本流程。现有脚本能够自动发现整理好的试卷 JSON 并生成数据库 SQL，PDF 的内容提取和校对由执行者负责。

## 目录与分类

```text
data/
├── inbox/                              # 新下载、待识别的 PDF
├── sources/                            # 已识别的原始 PDF
│   ├── cet4/2026-06/2026-06-CET4-1.pdf
│   ├── cet6/YYYY-MM/...
│   └── neep/YYYY-MM/...
└── papers/                             # 校对后的结构化试卷
    ├── cet4/2026-06/cet4-2026-06-1.json
    ├── cet6/YYYY-MM/...
    └── neep/YYYY-MM/...
```

目录分类和数据库的 `exam_level` 对应如下：

| 考试 | 目录 | `exam_level` |
| --- | --- | --- |
| 四级 | `cet4` | `CET4` |
| 六级 | `cet6` | `CET6` |
| 考研英语 | `neep` | `NEEP` |

以卷面标题和内容确认考试、年份、月份、套次；文件名只作为线索，不能按下载日期或文件修改时间填写考试时间。考研英语一、英语二必须分别识别，在 `variant`、标题和稳定 ID 中区分，避免混为同一张卷。沿用实际套次信息填写 `set_no`。

能够确认的试卷直接归档并新增，不必询问用户常规分类问题。确实缺少身份信息或存在冲突时，先保留原件并说明待确认项；只有用户授权本轮批量处理时，才继续处理同批中其他明确的试卷。

## 执行步骤

### 1. 发现文件与去重

- 先查看 Git 状态，保留与本次任务无关的修改。
- 扫描 `data/inbox/` 和用户指定位置；兼容 `data/` 根目录、旧 `data/papers/` 中尚未归档的 PDF。不要重复处理 `data/sources/` 中已经导入的原件。
- 读取卷面，检查 PDF 页数及是否含答案页；必要时提取文本、查看页面或 OCR，不能只根据文件名判断。
- 与现有原件的内容哈希、试卷身份和 JSON 比较。同一文件不同名字只导入一次；同一套卷的不同版本先核对差异，不能直接覆盖已有内容。
- 确认后将原件归档至 `data/sources/<考试>/<年月>/`。保留原始 PDF，不修改其页面内容，不删除尚未确认的文件。答案册等配套文件与对应试卷放在同一来源目录。

### 2. 提取全部非听力内容

按 PDF 的实际章节和顺序整理，包含写作、完形或选词填空、长篇或匹配阅读、仔细阅读、翻译，以及试卷中的其他非听力题。不同考试按实际结构处理，不套用固定的“四级六章节、32 题”模板。

必须保留原文、题干、题号、全部选项和答题要求。真实试卷不能改写成模拟卷，也不能只导入第一篇阅读。

逐页核对以下易错位置：

- 跨页段落、页尾与下一页接续的句子；排除页眉、页码和水印。
- 双栏选项的顺序及完整文本，不能把 A/C、B/D 错拼为 A/B/C/D。
- 选词填空的所有空位和完整词库；匹配阅读的所有段落标号。
- 英文大小写、引号、缩写、断行连字符；中文翻译材料的标点和完整段落。
- 写作的字数、任务要求及其他限制，阅读题与对应文章的关联。

例如现有四级第 2 套长篇阅读包含 A–P 共 16 段，末尾段落跨页；不能在看到部分题目或翻页后提前结束文章。

### 3. 生成试卷 JSON

保存到 `data/papers/<考试>/<年月>/<试卷ID>.json`。字段以 [数据契约](../packages/contracts/src/exam.ts) 为准，不新增未经支持的字段。

| 层级 | 需要整理的内容 |
| --- | --- |
| 试卷 | `id`、`exam_level`、`year`、`month`、`set_no`、`variant`、`title`、来源与答案说明、`sections` |
| 章节 | `id`、`kind`、`title`、`instructions`、`paragraphs`、`study_paragraphs`、`questions` |
| 题目 | `id`、`type`、`prompt`、`options`、`answer`、`explanation`、`points` |

实际导入的试卷使用 `content_state: "local"`、`content_kind: "imported"`、`is_demo: false`。没有可核实的来源网址时，`source_url` 填 `null`，不编造链接。

考研的 `year` 使用卷面考试年度，`month` 表示初试月份；例如卷面“2024 年英语一”使用 `neep-2024-12-english-1`，页面按年度与英语一、英语二区分，不展示会混淆考试年度和实际举办日期的月份。

带漫画、统计图或其他原题图片的章节可增加 `images: [{ src, alt }]`。从原 PDF 直接提取图片，保存在 `apps/web/public/papers/<试卷ID>/`，`src` 使用 `/papers/` 下的本地图片路径，`alt` 准确描述题图和图中数据；不能用改画的示意图替换原题。图片同时在精读和做题材料中展示。分值 `points` 支持 0.5 分的倍数，按原卷填写；考研完形每题 0.5 分，不套用四级选词填空的公共词库。

`paragraphs` 保存做题模式使用的原始材料；`study_paragraphs` 保存适合逐句阅读的英文材料：

- 普通阅读保留英文文章和段落顺序。
- 选词填空在做题材料中保留空格；精读材料按经过核对的参考答案补全。
- 匹配阅读在做题材料中保留段落标号；精读材料去掉独立的标号，保留全部段落。
- 写作保留原始任务要求，不生成示范作文来替换它。
- 中文翻译题保留原始中文材料；没有原卷英文材料时，`study_paragraphs` 为 `[]`，不为导入而生成英文答案。

AI 精读的逐句翻译、语法结构、句型、重点单词与词组保存在数据库缓存中，不提前写入试卷 JSON。新增试卷时不批量生成精读，不让做题模式调用 AI。

### 4. 核对答案与稳定标识

有随卷答案时逐题核对并注明来源。没有答案页时，客观题可依据原文整理可靠的参考答案，在 `description` 和题目 `explanation` 中明确说明，不能称为官方答案。写作、翻译等主观题没有参考答案时使用 `type: "text"`、`options: []`、`answer: null`。

当前数据契约要求选择题具有有效选项和匹配的参考答案。如果某题确实无法判断，保留待处理原件并报告该题，不能猜答案、删题或伪造数据绕过检查。处理其他试卷时仍遵守用户指定的批次和逐张检查节奏。

首次导入时确定稳定 ID，例如：

```text
试卷：cet4-2026-06-1
章节：cet4-2026-06-1-section-4
题目：cet4-2026-06-1-section-4-q-46
```

题目 ID 保留卷面题号，章节 ID 用于区分不同章节中的重复题号。考研英语一、英语二的试卷 ID 加入区分信息，例如 `neep-YYYY-MM-english-1` 与 `neep-YYYY-MM-english-2`；ID 中的年月应替换为已确认的考试信息。

文件移动不改变已存在的 ID、原文或章节顺序。不要为了新增一张卷而重排旧卷章节、修改句子切分规则、清库或删除缓存。新增使用稳定 ID 的数据库 upsert；修改原文会影响精读缓存匹配，不能当作无关格式修改处理。

### 5. 生成数据并检查

在项目根目录运行：

```bash
npm run seed:generate
npm run check
npm run build
```

生成器递归读取 `data/papers/` 中的 JSON，检查格式与重复 ID，并同步生成：

- `db/init/009_seed_papers.sql`
- `db/migrations/009_seed_papers.sql`

两份 SQL 都需随本次导入提交，不手工维护其中某一份。增加受支持分类的试卷无需逐张修改路由或导入脚本；出现尚未支持的真实题型时，应补齐必要支持并验证，不能偷偷改成别的题型。

本地已有数据库需应用部署用 SQL 后再验证数据；生产环境由部署脚本执行。校验 JSON 与 PDF 的章节数、题数、段落数、选项数量及原始题号，不能仅凭类型检查成功认定提取准确。

### 6. 提交、部署和验收

- 检查本次差异，只提交新增原件、JSON、生成 SQL 和确有必要的配套修改，排除无关改动和临时提取文件。
- 按项目约定提交并推送当前分支；`main` 触发 [自动检查与部署](CI_CD.md)。其他分支不自动部署到生产，应如实说明状态。
- 检查 GitHub Actions 结果。部署脚本会将新增数据导入 PostgreSQL，保留已有试卷、做题记录与精读缓存。
- 运行公开站点验证：

```bash
DEPLOY_URL=https://cet.fulafu.com npm run verify:deployment
```

自动验证会根据本地 JSON 核对分类列表、试卷信息、题目、原文和精读句子。再查看新增试卷在分类列表中的入口、做题材料和精读原文；确认旧卷仍可使用。检查页面本身不需要付费生成精读，也不应批量创建线上做题记录。

删除本地 JSON 不会自动删除数据库试卷。用户明确要求删除时，需要单独处理关联数据及迁移，不能把新增流程当作清理整个题库的操作。

## 完成后报告

简要说明新增了哪些试卷、非听力章节和题数，答案的来源或缺项，以及检查、提交和上线结果。若有待确认文件，列出原因和具体需要的信息；不要将仍未完成的试卷报告为已上线。
