# 日常审批模拟数据

`scripts/seed-approval-lifelike.mjs` 是手动使用的数据工具，不会在迁移、登录、启动或部署时自动执行。必须明确传入现有真实账号的 UUID；默认只检查并输出计划，加 `--apply --backup PATH` 才会写入。数据库和 Blob 配置沿用 API 运行环境，不把连接字符串写入参数或文档。

准备 API 构建产物及 `data/approval-demo` 图片后，在 API 相同环境运行：

```sh
node scripts/seed-approval-lifelike.mjs --target-user USER_UUID
node scripts/seed-approval-lifelike.mjs --target-user USER_UUID --apply --backup /private/path/approval-before-seed.json
```

数据包含 9 个模拟联系人（复用之前 3 个“演示”账号）、6 位已确认好友、2 条待处理申请、1 条发出的申请，以及 23 条日常审批。场景有阅读、运动、出游、装备清单和收纳采购；包括本人执行、代他人申请、三方审批、驳回、补充文字和图片、审批人调整时间、待评分、完成、超时零分、未批准过期和取消。过去七天的阅读记录有不同评分和实际内容，不用同一秒批量填满时间线。

头像由脚本绘制的原创矢量人物生成，经过现有图片服务压缩上传 Blob。地点照片是 CC0 公开许可素材，用作模拟材料，不是真实用户出游的证明。图片与对应的材料事件绑定，原材料和补充材料分别保留，使用既有缩略图和私有预览接口。

账号的 `openid` 保留 `demo-approval-` 前缀；新增请求及事件的 ID 来自固定命名空间，事件 `payload_json.seed` 为 `approval-lifelike-v1`。页面显示自然昵称和内容，不插入假的微信身份或修改目标用户自己的昵称、头像。模拟评分会进入该测试账号的统计。

重复运行会跳过已有场景，不重置用户已经操作过的审批，不重复插入图片和评分，也不重新开启已处理的好友申请。已有审批保留；之前的占位账号只在仍使用默认演示昵称时改名，已有头像不覆盖。脚本遇到既有未确认或屏蔽的关系会停止，不绕过它们。

应用前以 0600 权限保存原审批数据快照，文件使用排他创建，避免覆盖旧备份。备份包含私有账号信息，应存放在服务器私有目录，不提交 Git。
